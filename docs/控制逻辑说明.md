# 云台双轴控制逻辑说明

对应代码：`Core/Src/yuntai_task.c`（检查点 `v1.0-双轴可用`）

---

## 一、机械结构决定了全部控制结构

### 1.1 从下到上的装配

```
底盘（手 / 小车）
  └─ 偏航电机（水平转，绕竖直轴）
       └─ 中间平台   ← IMU 和俯仰电机都装在这里
            └─ 俯仰电机（上下转，绕水平轴）
                 └─ 激光发射器
```

要点只有一句：**IMU 装在中间平台上 —— 在偏航电机之上、俯仰电机之下。**

后面所有"为什么两个轴用完全不同的控制方式"，根子都在这句话上。

### 1.2 可观测性：某个传感器能不能当反馈？

判据很简单：**我让这个电机动一下，这个传感器的读数会不会跟着变？**

| | 偏航电机转 | 俯仰电机转 |
|---|---|---|
| IMU 姿态角 | 跟着变 ✅ | **完全不变** ❌ |
| 偏航电机编码器 | 跟着变 ✅ | 不变 |
| 俯仰电机编码器 | 不变 | 跟着变 ✅ |

（编码器各自装在电机转轴上，只能看见自己那根轴；IMU 在中间平台上，所以看得见偏航、看不见俯仰。）

由此直接推出两条结论：

1. **偏航**：IMU 看得见偏航电机的动作 → 可以把 IMU 测出的偏航角**直接当反馈**做闭环。
2. **俯仰**：IMU **看不见**俯仰电机的动作 → **绝对不能**拿 IMU 的俯仰角当反馈。
   硬这么干的话，控制器会认为"我驱动了它却毫无反应"，于是拼命加大输出，电机朝一个方向狂奔
   —— 这个现象我们实测复现过。
   → 只能用**俯仰电机自己的编码器**当反馈。

### 1.3 IMU 在两个环里的角色完全不同

这一点最容易被含糊过去，但它是理解俯仰环的钥匙：

- **偏航环里，IMU 是「反馈」**：它的读数**就是**我们要控制的那个量。
  控制目标 = 让这个读数保持在上电时刻的值不变。
- **俯仰环里，IMU 是「扰动测量器」**：俯仰电机怎么转它都不动，所以它测到的俯仰角变化
  **只可能来自底盘倾斜**。换句话说，**IMU 专门用来看"底盘歪了多少"**，
  它负责回答"目标角应该是多少"，但**不回答**"现在实际到哪儿了"。

> 一句话记住：**偏航靠 IMU 测量结果，俯仰靠 IMU 生成目标、靠编码器测量结果。**

## 二、几个必须先讲清楚的概念

### 2.1 反馈、误差、闭环

- **反馈**：能被控制器实时读到的、代表"现在实际是什么状态"的信号。
- **目标值（setpoint）**：我们希望它变成什么状态。
- **误差**：`误差 = 目标值 − 反馈值`。
- **闭环**：控制器只看误差来决定输出，输出又会改变反馈值，从而改变误差 —— 形成一圈回路。

本工程里 PID 用的就是 `误差 = 目标 − 反馈`（见 `pid.c`）：

```
比例项 P = kp × 误差
积分项 I = ki × Σ(误差 × dt)        // dt 是控制周期，这里 5ms
微分项 D = kd × (误差 − 上次误差) / dt
输出     = P + I + D
```

- **P**：误差越大推得越猛。它是主力。
- **I**：误差存在时间越长累积越大，专门用来消掉"一直差一点点但推不动"的**稳态残差**。
- **D**：看误差**变化得快不快**，用来**刹车**，抑制过冲和振荡。误差不变时 D 项为 0。

### 2.2 「前馈」到底前馈了什么

这是最容易被当成咒语的一个词，说清楚就好懂了。

**反馈的思维方式**：先等误差出现，再根据误差去纠正。**误差必然先存在一段时间。**

**前馈的思维方式**：如果这个扰动我**能提前直接测出来**，那我就不用等误差出现，
直接把测到的扰动换算成"电机应该出多少力"，一次性加上去。

本工程两个轴各有一路前馈，用的都是**陀螺仪测到的平台转动角速度**：

| | 前馈项 | 物理含义 |
|---|---|---|
| 偏航 | `YAW_FF_SIGN × gyro[2] × 66.85` | 平台**绕竖直轴**转多快（rad/s）→ 直接换成电机转速 |
| 俯仰 | `PITCH_FF_SIGN × gyro[1] × 15` | 平台**绕水平轴**转多快（rad/s）→ 直接换成电机转速 |

**为什么需要它**：电机的静摩擦脱困速度大约在 **10 rpm 量级**（推不动就是因为指令太小）。
而 PID 的**比例项**在误差很小时输出很小 —— 偏航 1° 误差只有 3.5 rpm，根本推不动电机。
所以如果只留 PID，手慢慢扭底盘时电机**完全没反应**，看起来像"坏了"。
（历史上水平电机"不工作"就是这个原因。）

前馈一来就是几十 rpm，直接越过静摩擦门槛，**手一动电机立刻跟着动**。
角度 PID 则退居二线，只负责慢慢把角度精修回去。

> 单位换算：`1 rad/s = 9.55 rpm`。偏航前馈 66.85 rpm/(rad/s) ≈ 7 倍理论抵消量，
> 俯仰前馈 15 rpm/(rad/s) ≈ 1.6 倍。**故意过量一点**，才能确保越过静摩擦。

### 2.3 「串级（级联）控制」

两个控制器**嵌套**：外面那个的输出，是里面那个的目标值。

本工程俯仰轴就是：
- **外环（MCU 里，200Hz）= 位置环**：输入"电机应该在哪"，输出"电机应该以多快转"。
- **内环（驱动器内部，频率远高）= 速度环**：输入"该以多快转"，输出真正的电流/力矩。

**两个电机始终都工作在速度模式（寄存器 `0x0060` 写 1）**。
驱动器内部只跑速度环，位置环完全由 MCU 自己算 —— MCU **从头到尾没有下发过任何位置指令**。

### 2.4 静摩擦脱困速度

直驱云台电机在指令转速很小时，因为静摩擦和齿槽力矩，**根本转不起来**。
实测"能转起来的最小指令"在 **10 rpm 量级**。

这是整个调试里最关键的物理约束：

- 指令 < 脱困速度 → 电机不动，PID 误以为"推不动"，于是继续加
- 这就是"小误差没反应、大误差才动"的死区来源

### 2.5 陀螺零偏与姿态角

- **陀螺仪**测的是**角速度**（rad/s），不是角度。要拿角度必须**积分**。
- 陀螺仪静止时读数不是精确的 0，而是有一个固定的**小偏置**（零偏）。
  这个偏置会被积分**无限累加** → 角度会以恒定速度漂走。
- 所以上电时通常会**静止采样一段时间求平均**，把这个偏置测出来，之后每次读数减掉。

> **本工程没有做这个补偿**（曾经做过，但因为会卡死启动流程又删掉了，原因见 3.1）。
> 直接拿原始陀螺值用 —— 原版第一次提交的代码就是这么做的，能跑。
> 代价是偏航角会因零偏残留而缓慢漂移（见 2.6）。

### 2.6 为什么偏航角一定会缓慢漂移（重要的物理局限）

姿态解算（Mahony）做了两件事：
1. **积分陀螺**得到角度 —— 响应快，但会漂。
2. **用加速度计修正** —— 加速度计能测出**重力方向**，所以能知道"哪个方向是下"，
   据此把俯仰角和横滚角慢慢拉回正确值（永久的绝对基准）。

**但加速度计测不出"朝哪个方向"（方位角）。** 没有磁力计就没有绝对方位基准。
所以：

$$\text{俯仰角、横滚角} = \text{有绝对基准（靠重力）} \qquad
\text{偏航角} = \text{纯陀螺积分，无绝对基准}$$

**⟹ 偏航角的绝对数值没有意义，且会随着零偏残留缓慢漂移。**
这带来两个后果：

- 我们只能用**相对量**：上电瞬间锁一个 `yaw_target`，之后让偏航角相对它保持不动。
- 零偏残留造成的漂移**无法被任何算法区分**：**零偏残留 Δb 造成的"平台在转"和"底盘在转"，
  在数学上完全不可区分** —— 两种情况陀螺读数和姿态解算全都正常。
  所以不要指望"静止时同步基准"之类的补偿能救它（运行中角速度不为零，永远不触发）。
  彻底解法是加磁力计；退一步是把上电零偏采样做准 ——
  但这正是本工程已经删掉的那一步（原因见 3.1），**当前接受这个漂移**。

### 2.7 为什么俯仰角在剧烈晃动时会短暂失准

加速度计量程只有 ±3g，且有线加速度干扰。猛烈晃动时它测到的"重力方向"会被线加速度污染，
所以 Mahony 用到的修正量会短暂出错。

**注意**：俯仰环的目标角来自 `imuAngle[PITCH]`，所以这个误差会短暂影响俯仰的目标。
（偏航角不依赖重力，所以不受影响 —— 这也是历史上"俯仰飘、偏航不飘"的原因之一。）

### 2.8 采样率为什么必须和实际调用率一致

Mahony 内部用 `halfT = 0.5 / sampleFreq` 作为四元数积分步长。
如果 `sampleFreq` 写成 1000，而实际每 2ms（500Hz）调用一次，
那么每次积分只走了真实时间的一半 —— **整条姿态链处在"半速时间"里，角度只报真值的一半**。

原版代码就有这个错误。它当时之所以"看起来能用"，是因为俯仰当时用的是**原始陀螺**做前馈
（陀螺读数不经姿态解算，所以不受影响），而偏航环的反馈增益则被悄悄砍了一半。

现已修正为 `mahonySampleFreq = 1000.0f / IMU_PERIOD = 500`。
**代价**：姿态报量变成原来的 2 倍，所有"用姿态做反馈或目标"的环路增益同步翻倍 ——
所以偏航的 `YAW_KD` 从原版的 10 降到 5，以复原原来实测过的等效阻尼。

## 三、上电启动过程（约 3.4 秒，共 6 个状态）

| # | 状态 | 时长 | 对电机做什么 | 对 IMU 做什么 |
|---|---|---|---|---|
| 0 | 上电自由态（`yuntai_init()`） | — | **不发任何指令**。驱动器停在上电默认态（未使能闭环）→ **电机是自由的，能被手掰动** | 只初始化 CAN |
| 1 | `ST_BMI_INIT` | ~0.2s | 不发指令 | 每 200ms 试一次 `BMI088_init()`，失败重试 |
| 2 | `ST_WAIT_MOTOR_BOOT` | **2.0s** | 不发指令 | 不读。**纯延时**，等驱动器上电自检完成 |
| 3 | `ST_ENTER_CLOSED_LOOP` | 0.5s | 发 `0x00A2`（进入闭环）到两条总线，每 100ms 重发防丢帧 | 不读 |
| 4 | `ST_SET_SPEED_MODE` | 0.5s | 发 `0x0060 = 1`（**速度模式**），同样每 100ms 重发 | 不读 |
| 5 | `ST_LOCK` | 0.2s | **不发指令**（电机保持 0 速） | 读 IMU 并**锁定基准**：`yaw_target`、俯仰基准；`PID_Init` |
| 6 | `ST_RUN` | 永久 | 每 **5ms** 发一次速度指令 | 每 **2ms** 读一次 |

### 3.1 为什么不做陀螺零偏标定（重要设计教训）

原版第一次提交的代码是**直接拿原始陀螺值用**的，没有零偏补偿，照样能跑。
我后来加了"静止采样求平均"，它引入了一个会**卡死启动流程**的故障：

- 它要求连续采满 600 个"没在动"的样本，**任何一个样本超过阈值
  (0.06 rad/s ≈ 3.4°/s) 就把已采样本整批清零重来**。
- 如果这颗 BMI088 的陀螺零偏本身就超过这个阈值，就**永远采不满**，
  只能干等到 12 秒超时放行。
- 更致命的是：走不到这一步，后面的 `ST_ENTER_CLOSED_LOOP` 就永远不执行，
  电机停在**未使能**状态 —— 表现就是**云台一直是软的、能被手掰动**。

**代价权衡**：不做零偏补偿，偏航角会因零偏残留缓慢漂移（见 2.6）。
这个漂移可以接受，而"卡死启动"不可接受 —— **宁可漂，不能卡**。

**设计规则（写进后续所有修改）**：
> 启动路径上只允许**纯延时**推进。
> 凡是"要满足某条件才能往下走"的逻辑，一旦条件因噪声或环境永远不满足，
> 整个状态机就停在原地 —— 而表现是"云台一直是软的"，**极难定位**。
> 带条件的逻辑只能放在 `ST_RUN` 里做**后台降级**。

### 3.2 两处绝对不能动的设计

1. **第 2 阶段那 2.0 秒是刻意的**：驱动器上电自检需要时间，控制模式指令发太早会被忽略。
   这就是历史上"上电偶尔完全失去控制"的根源。
2. **`0x0060`（控制模式）和 `0x00A2`（闭环使能）只在第 3、4 阶段发，进 `ST_RUN` 后一律不再碰。**
   运行期反复写这两个寄存器会不断复位驱动器内部的运动状态 ——
   表现就是**水平电机完全不动**（偏航指令本来就只有几 rpm，一复位更起不来；
   俯仰因为前馈指令大，复位后还能立刻重新脱困，所以看不出问题）。

### 3.3 俯仰在 `ST_RUN` 里还有一步

俯仰要等到**第一帧编码器反馈**才算真正闭环：

| 子状态 | 条件 | 行为 |
|---|---|---|
| 反馈未就绪 | 50ms 内收不到编码器帧 | `PID_Reset`，**退化成纯角速度前馈**（只响应转动，不响应慢漂） |
| `pitch encoder online` | 首次收到有效编码器帧 | 锁 `pitch_motor_locked`，之后是**编码器位置环 + 前馈** |

这个基准**只锁一次、永不重建**。曾经写成"反馈恢复时重建"，结果剧烈晃动下把错误的瞄准方向固化了下来。

### 3.4 怎么判断卡在哪一步

代码里每次状态切换都有一句打印，按顺序应该是：

```
=== YunTai Start ===  →  BMI088 OK  →  startup delay done
→  motor closed loop  →  motor speed mode
→  === STABILIZATION ACTIVE ===  →  pitch encoder online
```

**缺哪条就说明卡在对应状态。** 几个典型情况：

- `BMI088` 反复重试 → SPI2 预分频不是 32（历史上踩过）。
  这是启动路径上**唯一还剩的条件判据**（因为没 IMU 就没法控制），其余全是纯延时。
- 第 2 阶段固定 2 秒，**不会卡住**（见 3.1 的教训）。
- 已经有 `motor speed mode` 却不动 → CAN 或驱动器侧，**不是 PID 问题**
- 到了 `STABILIZATION ACTIVE` 但不出 `pitch encoder online` → 编码器反馈没收到，俯仰退化成了纯前馈

## 四、主循环的节拍

```
while (1) { yuntai_control_loop(); }        // main.c，裸机无 RTOS

yuntai_control_loop():
    now = HAL_GetTick()
    switch (状态)
```

用 `HAL_GetTick()`（1ms 分辨率）做分频，得到两个节拍：

| 节拍 | 周期 | 频率 | 工作内容 |
|---|---|---|---|
| IMU 节拍 | 2ms | 500Hz | 读 BMI088 → 减去陀螺零偏 → Mahony 姿态解算 → 四元数转欧拉角 |
| 控制节拍 | 5ms | 200Hz | 算出两轴的输出并下发 CAN 速度指令 |

**控制周期用 5ms 而不是更快**，是因为这是与原版一致的实测值：PID 的积分项和微分项都乘/除 `dt`，
换个周期整组参数都要重新整定。

## 五、偏航控制逻辑

### 5.1 控制目标

**保持上电瞬间的朝向不变。** 即：不管底盘怎么绕竖直轴转，中间平台（连带激光）的绝对方位角不变。

### 5.2 反馈

`imuAngle[YAW]` —— Mahony 解算出的偏航角（弧度）。

### 5.3 目标

`yaw_target` = 在 `ST_LOCK` 阶段锁定的 `imuAngle[YAW]` 的初值，**之后是一个常数，永不变动**。

### 5.4 计算流程（每 5ms 一次）

```c
yaw_err = angle_diff_rad(yaw_target, imuAngle[YAW]);   // 目标 - 反馈，归一化到 ±π
PID_Update(&yaw_pid, yaw_err, 0.0f, dt);

yaw_cmd = yaw_pid.out + YAW_FF_SIGN * gyro[2] * (YAW_FF_GAIN / 100.0f);

限幅到 ±YAW_OUT (50 rpm)
下发 jc_set_speed_rpm_x100(&hfdcan1, YAW_ID, yaw_cmd * 100)
```

中间那个 `angle_diff_rad` 做的是**角度差值归一化**：把差值折到 ±180° 内。
没有它的话，比如目标 179°、当前 −179°，实际只差 2°，却会算出 358° 的误差，电机就会朝错误方向猛转一整圈。

### 5.5 当前参数与它们的物理意义

| 参数 | 值 | 单位 | 物理意义 |
|---|---|---|---|
| `YAW_KP` | 200 | rpm/rad | 1° 误差（0.0175 rad）→ 3.5 rpm |
| `YAW_KI` | 30 | rpm/(rad·s) | 1° 误差每秒把指令抬 0.52 rpm |
| `YAW_KD` | 5 | rpm/(rad/s) | 误差变化越快，刹车越狠 |
| `YAW_OUT` | 50 | rpm | 输出限幅（约 300°/s 的补偿能力） |
| `YAW_ILIM` | 10 | — | 积分限幅 |
| `YAW_FF_GAIN` | 6685 | (rpm×100)/(rad/s) | 即 66.85 rpm per (rad/s) |
| `YAW_FF_SIGN` | −1 | — | 方向：反向补偿 |

### 5.6 偏航环的物理直觉

- **快动**：手快速扭底盘 → `gyro[2]` 立刻很大 → 前馈给出几十 rpm → 电机立刻反向跟上。**这是主力。**
- **慢漂**：零偏残留让角度慢慢跑 → `gyro[2]` 几乎为 0，前馈不起作用 → 靠 PID 的 P 和 I 慢慢把角度拉回来。
- **静止保持**：误差为 0，前馈为 0，输出 0，电机不转。**这正是我们想要的。**

### 5.7 已知弱点

`YAW_KI × YAW_ILIM = 30 × 10 = 300 rpm`，远大于输出限幅 50 rpm。
意味着**只要误差持续存在足够久，积分项单独就能把输出顶到满幅**（约需 96 秒）。
而且输出限幅是**硬夹**，积分项不会因为输出饱和而反向退出（没有抗积分饱和）。
所以如果出现"偏航慢慢持续朝一个方向转、越转越快"，优先怀疑这里：
把 `YAW_ILIM` 降到 `50/30 ≈ 1.6` 以下，让积分单独就顶不满输出。

## 六、俯仰控制逻辑

### 6.1 控制目标

**保持激光的俯仰指向不变。** 底盘前后倾斜时，俯仰电机要反向转同样的角度来抵消。

### 6.2 反馈

`pitch_fb.pos_deg` —— **俯仰电机编码器**测到的电机轴绝对角度（度）。

来源有两条路，谁先到用谁（都在 CAN 接收中断里解析）：
1. 每条速度指令的回复帧（命令字 `0x2A`），位置是**有符号 24 位大端 ÷100 = 度**
2. 主动读寄存器 `0x0008` 的回复（命令字 `0x43`），位置是**有符号 32 位大端 ÷100 = 度**

### 6.3 目标（每 5ms 重算，不是常数！）

```c
dplat  = imuAngle[PITCH] - pitch_plat_locked;   // 底盘倾角的变化量（弧度）
target = pitch_motor_locked - dplat * RAD2DEG;  // 目标电机角（度）
```

- `pitch_plat_locked`：上电时 IMU 测到的俯仰角
- `pitch_motor_locked`：上电时编码器测到的电机角
- `RAD2DEG = 57.29578`：弧度 → 度

**物理意义**：底盘向上倾了 `dplat` 度，电机就要**反向**转 `-dplat` 度，激光指向才能不动。
那个负号就是"反向补偿"。目标角加软限位：相对 `pitch_motor_locked` 夹在 ±80° 内，防止绕线或撞机构。

### 6.4 计算流程（每 5ms 一次）

```c
err = target - pitch_fb.pos_deg;                        // 单位：度
PID_Update(&pitch_pid, err, 0.0f, dt);

cmd = pitch_pid.out + PITCH_FF_SIGN * gyro[1] * (PITCH_FF_GAIN / 100.0f);

限幅到 ±PITCH_OUT (50 rpm)
下发 jc_set_speed_rpm_x100(&hfdcan2, PITCH_ID, cmd * 100)
```

### 6.5 降级路径

若 50ms 内没收到任何编码器帧，`pitch_base_ok` 保持 0 或 `fb_ok` 变 0：

```c
PID_Reset(&pitch_pid);
下发 PITCH_FF_SIGN * gyro[1] * 15 * 100   // 纯前馈，没有位置环
```

此时电机只对**转动速度**有反应，对缓慢倾斜**没有**反应。
所以"俯仰只对快动有响应、慢慢倾斜没反应"这种情况，先怀疑**编码器反馈断了**，而不是 PID 没调好。

### 6.6 当前参数与它们的物理意义

| 参数 | 值 | 单位 | 物理意义 |
|---|---|---|---|
| `PITCH_KP` | 2.8 | rpm/度 | 1° 误差 → 2.8 rpm |
| `PITCH_KI` | 10 | rpm/(度·s) | 消静差 |
| `PITCH_KD` | 0.0002 | rpm/(度/s) | 很小，几乎不起作用 |
| `PITCH_OUT` | 50 | rpm | 输出限幅 |
| `PITCH_ILIM` | 0.6 | — | 积分限幅；`ki × ilim = 6 rpm`，积分单独顶不过静摩擦，符合预期 |
| `PITCH_FF_GAIN` | 1500 | (rpm×100)/(rad/s) | 即 15 rpm per (rad/s) |
| `PITCH_FF_SIGN` | −1 | — | 方向：反向补偿 |
| `PITCH_LIMIT_DEG` | 80 | 度 | 相对上电位置的行程软限位 |
| `PITCH_FB_TIMEOUT_MS` | 50 | ms | 反馈超时后降级为纯前馈 |

### 6.7 俯仰环的物理直觉

- **快动**：手快速前后倾 → `gyro[1]` 很大 → 前馈给出几十 rpm → 电机立刻反向跟上。
- **慢动 / 静止倾斜**：前馈接近 0，靠**位置环**干活。IMU 测出底盘倾角变化 → 目标角改变 →
  编码器与目标角之间产生误差 → PID 把误差变成转速 → 电机转到新目标角。
- **静止保持**：目标和编码器一致，误差为 0，输出 0。
- **前馈与位置环的分工**：位置环**精确定位**（慢，但最终一定到位），前馈**抢先响应**（快，但只是近似）。
  两者相加再交给驱动器的速度环执行。

## 七、两轴对照

| | 偏航 Yaw | 俯仰 Pitch |
|---|---|---|
| 被控量 | IMU 偏航角 | 俯仰电机编码器角度 |
| **IMU 的角色** | **反馈**（就是被测量本身） | **扰动测量 / 目标生成器**（不在反馈路径上） |
| 为什么 | 偏航电机转动**会**改变 IMU 姿态 | 俯仰电机转动**不会**改变 IMU 姿态 |
| 环结构 | 单环角度环 | 串级：MCU 位置环（外）+ 驱动器速度环（内） |
| 驱动器模式 | 速度模式 `0x0060=1` | 速度模式 `0x0060=1` |
| MCU 下发 | 速度指令（rpm） | 速度指令（rpm） |
| **目标值的性质** | **常数**（上电锁一次） | **每周期重算**（随底盘倾角变化） |
| 前馈来源 | `gyro[2]`（绕竖直轴角速度） | `gyro[1]`（绕水平轴角速度） |
| 有没有绝对的姿态基准 | 没有（无磁力计，会漂） | 有（加速度计测重力） |
| 反馈来源 | IMU 姿态解算 | 电机编码器 |
| 反馈丢失时 | 无降级路径 | 退化为纯前馈 |
| 转向的物理量 | 绕竖直轴（扭转） | 绕水平轴（前后倾） |

**启动时序、控制周期（5ms）、速度模式、CAN 协议、静摩擦脱困约束 —— 两轴完全相同。**

## 八、CAN 通信约定（JC 系列驱动）

| 项目 | 值 |
|---|---|
| 发送 ID | `0x600 + 驱动器ID`（本工程两条总线的 ID 都是 1） |
| 回复 ID | `0x580 + 驱动器ID` |
| 偏航总线 | FDCAN1 = PD0(RX) / PD1(TX) |
| 俯仰总线 | FDCAN2 = PB5(RX) / PB6(TX) |
| 自动重传 | **关闭**（丢帧就是永久丢了，所以启动阶段要重发几次） |
| 滤波器 | 范围 `[0x000, 0x7FF]` 全收 |

用到的指令：

| 功能 | 命令字 | 寄存器 | 数据 |
|---|---|---|---|
| 设置转速 | `0x23` | `0x0021` | 有符号 32 位大端 = rpm × 100 |
| 进入闭环 | `0x2B` | `0x00A2` | `0x0001` |
| 设置控制模式 | `0x2B` | `0x0060` | `1` = 速度模式 |
| 读实时位置 | `0x43` | `0x0008` | 回复：有符号 32 位大端 ÷100 = 度 |
| 写指令回复 | `0x2A` | — | `位置(24位) 速度(16位) 电流(16位)` |

## 九、当前已知的弱点与改进方向

1. **偏航积分限幅过大**（见 5.7），积分单独就能顶满输出。建议降到 1.6 以下。
2. **没有抗积分饱和**：`pid.c` 只把积分夹到 ±`integral_limit`，不会因为输出饱和而回退。
3. **控制周期用 `HAL_GetTick()`**（1ms 分辨率）分频，有 1ms 抖动。
   要完全无抖动应改用硬件定时器中断做时基。
4. **俯仰的目标角依赖 `imuAngle[PITCH]`**，而 IMU 俯仰角在剧烈运动时会受线加速度干扰短暂失准。
5. **偏航角没有绝对基准**，零偏残留造成的漂移在数学上无法与"底盘真在转"区分
   （见 2.6）。彻底解法是加磁力计。
6. **偏航前馈符号需现场确认**：若上电发现偏航顺着转动方向越跑越快，
   把 `YAW_FF_SIGN` 改成 `+1.0f`。

## 十、调试时的排查顺序（推荐）

1. **先确认通路**：把 `YAW_OPENLOOP_TEST` 置 1，忽略 PID 直接给偏航电机 30 rpm。
   - 转起来 → CAN + 速度模式通路正常，问题在控制环
   - 不转 → 问题在驱动器 / 接线 / ID / 供电，**调 PID 完全无用**
2. **再看启动打印**，确认走完了 6 个状态（见 3.4）。
3. **最后才动 PID 参数**，而且一次只改一个，每次改完都提交一次 git 并打标签。
