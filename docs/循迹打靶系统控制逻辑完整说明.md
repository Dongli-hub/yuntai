- 11.4 H723 工程结构和 CubeIDE 配置
- K230 UART 帧解析

H723 控制周期对齐参考工程，改为 500 Hz。

## 2. 电机模式

Yaw 和 Pitch 均固定为 JC4310 速度模式：

```text
控制模式寄存器 0x0060 = 1
速度寄存器     0x0021 = rpm × 100
```

Yaw 的力矩模式开关被强制关闭，力矩测试也不再允许切换驱动器模式。

## 3. K230 到世界目标

输入角度误差：

```text
yaw_error_deg   = K230 yaw
pitch_error_deg = K230 pitch
```

K230 的 ASCII 视觉帧末尾增加 XOR 校验：

```text
payload*HH
```

`HH` 为 `*` 之前全部 ASCII 字节的异或值。H723 只有在校验正确时才解析
目标、距离和角度；字符丢失、小数点移位或字段粘连不会再作为有效目标进入
Alpha-Beta。

K230/H723 链路使用旧仓库验证过的 `115200 8N1`。2026-11-13 23:39 的记录
显示，`921600` 下 K230 约发送 32 帧/s，但 80% 以上帧 XOR 校验失败，H723
最终只得到约 5 帧/s。降低到 `115200` 后视觉数据量仍只有约 2.7 KB/s，
带宽余量充足，优先保证链路完整性。

K230 使用当前标定内参把靶心与实时激光光斑的像素差换算为真实角度：

```text
yaw_error_deg   = atan2(target_cx - laser_x, fx)
pitch_error_deg = atan2(target_cy - laser_y, fy)
```

固定 `0.14°/px` 近似已删除。角度进入视觉环前先过 `0.1°` 死区。随后用
K230 图像年龄、`40 ms` 固定链路补偿和 H723 IMU 历史恢复拍照时刻姿态：

```text
capture_latency_ms = K230_image_age_ms + 40 ms
capture_ms = H723_now_ms - capture_latency_ms
```

再生成世界测量：

```text
measured_yaw
  = capture_imu_yaw + VISION_YAW_DIR × yaw_error_deg

measured_pitch_motor
  = capture_motor_pitch
  + VISION_PITCH_DIR × pitch_error_deg
  + capture_platform_pitch
```

当前方向参数：

```text
VISION_YAW_DIR   = -1
VISION_PITCH_DIR = -1
```

2026-11-13 22:56 的联调数据证明：Yaw 取 `+1` 时，误差 `+0.23°` 对应
`+1.7 rpm`，随后误差增长到 `+10.99°`；负误差段也向负方向持续增大。
因此 Yaw 视觉目标必须取 `-1` 才是负反馈。后续实车方向检查确认 Pitch
跟随方向也需要取反，因此 Pitch 改为 `-1`。

测量值直接进入 Alpha-Beta 跟踪器。参数为：

```text
Alpha = 0.50
Beta  = 0.17
单帧残差限幅 = 0.40°
最大残差速度 = 90°/s
单帧残差门限 = 5°
coast = 450 ms
丢失重置 = 500 ms
```

跟踪器保存测量时刻的车辆累计转动角 `u_ref`。车辆在赛道上移动时：

```text
predicted_target
  = target + residual_rate × dt
  + (current_vehicle_yaw - u_ref)
```

因此，车身转动造成的目标方位变化由 `u_ref` 差分补偿，不会全部被误学成
目标残差速度。最终直接得到：

```text
world_yaw_target
world_pitch_target
world_yaw_target_rate
world_pitch_target_rate
```

不再执行“视觉 PID 输出速度 -> 积分成视觉偏置角”的第二层积分。

### 3.1 当前目标距离

距离不再使用“内框像素宽度/高度直接除焦距”作为主结果。每个已确认靶框
使用四个角点和当前标定内参重建靶面平面位姿，再用位姿把靶心从靶面坐标
变换到相机坐标系：

```text
target_camera = pose.camera_point(target_center_mm)

range_m = norm(target_camera) / 1000
depth_m = target_camera.z / 1000
```

该 `range_m` 是相机到靶心的三维直线距离，与参考工程
`vision/geometry.py` 的 `range_mm` 定义一致。主要处理保留：

- 原矩形识别、内外框判定和候选筛选
- 原实时白色激光亮斑识别；控制只接受当前帧新鲜光斑，不重放上一帧光斑
- 仿射/透视下由四角点恢复完整平面位姿
- Gauss-Newton 位姿细化，最多 2 次迭代
- 位姿重投影残差门限

控制只接受通过角点、残差和距离门限的位姿测距结果。位姿测距失败时 K230
直接发送 404，不再使用旧四边形近似距离或预测框作为控制兜底。日志中的
`distance_source=1` 表示本帧使用位姿测距，`0` 表示不可用于控制。

K230 矩形跟踪器也不再在候选缺失时静默复用上一帧靶框。当前帧没有合格
候选或内外框发生冲突时立即发送 404，使近边真实短时丢靶可在 H723 的
`aim`、`vision_hold_state` 和视觉帧间隔中明确看到。跟踪器关联状态最多
保留 3 个无候选帧，之后才进入完整重捕获；单帧漏检恢复后可立即重新关联，
不会再次执行完整的 3 帧确认。

激光光斑恢复为原来的单一路径：在靶框 ROI 内使用 LAB 高亮白色连通域，
最小像素数 `6`、最小密度 `0.45`，再经过尺寸、面积比例、长宽比、靶框
内部和跨帧跳变筛选。不使用灰度峰值恢复、固定点或上一帧光斑兜底。
位姿距离每个有效目标帧都重新计算。

靶框层级选择加强为内框优先：

- 内框候选评分倍数由 `2.0` 提高到 `4.0`。
- 外框换层评分由 `0.55` 降到 `0.25`，连续换层票数由 `2` 提高到 `4`。
- 删除“只有一个候选时强制标为内框”和“最终候选自动改标内框”两处逻辑。
- 已锁定内框后不接受外框候选。
- 确认阶段只允许原本不是内框的候选被标记为外框，避免正常内框被改层。

此前静态斜视角记录中，靶框宽度在 `96 px` 与 `110 px` 间切换，并产生
68 次单帧 `lost_reason=4`；这些强制改标路径是尺寸跳变和层级关联失败的
主要来源。

近目标跟踪新增两项低延迟优化：

1. 已锁定时，激光检测 ROI 收缩到上一帧光斑中心周围 `±56 px`，同时仍裁剪
   在靶框内部；上一帧光斑只用于确定搜索区域，不会作为控制点输出。
2. 靶框中心和激光中心的滤波系数按帧间运动自适应：静止时 `0.35`，
   大于 `10 px/帧` 时提高到 `0.80`，减少近距离快速移动时的视觉滞后。
3. 近距离大目标的候选预筛选从 `1.0` 倍框宽收紧到 `0.35` 倍框宽，在
   开销较大的明暗边沿采样前过滤掉大量背景四边形；远距离仍保留宽松门限。
4. 近距离靶框跟踪 ROI 的边距系数从 `0.30` 降到 `0.15`；激光局部搜索半径
   从 `56 px` 降到 `40 px`。远距离仍使用 `0.30/56 px`，丢失后的重捕获
   继续使用独立的全图搜索流程。

Python GC 周期由每 `150` 帧改为每 `300` 帧，减少运行中的周期性停顿。
不再使用的激光“保持上一帧光斑”分支、计数状态和调试字段已经从 K230 删除。
2026-11-14 19:14 记录中，近距离有效视觉约 `19.3 FPS`，远距离约
`23.7 FPS`，且近距离目标中心跳变更大，因此本次优化主要针对近距离处理量
和跟随滞后。

404 帧携带丢靶原因码：

```text
1 = 当前帧完全无候选靶框
2 = 靶框存在但位姿测距失败
3 = 靶框存在但激光光斑丢失
4 = 找到候选但关联/尺寸/中心等筛选失败
```

2026-11-14 直线联调中，原始位姿距离在路线近/远端约为 `0.60/1.67 m`，
对应实际约 `0.50/1.50 m`。因此对最终位姿距离应用两点线性标定：

```text
calibrated_range =
    0.9346 × raw_pose_range - 0.0607
```

标定后近/远端约为 `0.50/1.50 m`。该校正直接作用于位姿结果，不引入旧的
宽高像素测距。

当前相机标定参数保持不变：

```text
fx = 610.783983
fy = 621.307476
cx = 313.270140
cy = 238.263723
```

`fx/fy/cx/cy` 和畸变参数全部参与位姿重建和像素角度换算。K230 位姿测距
自检同时验证 `1.500000 m` 原始位姿结果和标定后的映射结果。

K230 位姿距离有效范围仍为 `0.30~2.00 m`。外框使用
`0.300 × 0.210 m`，内框使用 `0.260 × 0.170 m`。

## 4. Yaw 控制

### 4.1 底盘平移方位速度前馈

参考工程实际使用的是 `sin`，不是 `cos`：

```text
phi = wrap_±180(yaw_motor_angle - forward_offset)

geometry_rate
  = (57.29578 × v_lead / target_range)
  × sin(phi)
```

其中：

- `v_lead = v + 0.05 × dv/dt`，加速度前馈限幅使附加速度不超过 `±0.20 m/s`
- `target_range` 使用 K230 当前有效距离，最小 `0.15 m`，距离年龄不得超过
  `1000 ms`
- 不再乘 `0.72`、路线转角几何系数或近边起步系数
- `TRACK/APPROACH/PIVOT/EXIT` 均持续允许平移前馈，故障阶段关闭
- 平移速率不再额外限幅，避免几何模型被二次缩放

F103 首次从静止起步恢复 `1.2 s` smoothstep 目标速度斜坡：

```text
x = min(t / 1.2, 1.0)
v_target = 0.290 × x² × (3 - 2x)
```

该斜坡只在首次获得有效黑线并使能后触发；进入直角、丢线停车或后续普通
直线巡线时不会重新触发。H723 不再叠加额外的起步前馈开放斜坡。

### 4.2 底盘角速度前馈

F103 遥测给出底盘 `gyro_z`。H723 计算：

```text
chassis_gz_ff = -1 × chassis_gz
lead          = -1 × lead_gain(chassis_dgz/dt)
```

H723 在 `PIVOT` 阶段检测到底盘正在转弯后，使用参考工程的角加速度超前：

```text
lead = clip(0.10 × d(chassis_gz)/dt, ±80°/s)
```

超前在 `phase=1 APPROACH`、`phase=2 PIVOT`、`phase=3 EXIT` 时使能，
并在三个转弯阶段全部结束后再保留 `150 ms` 尾段。
底盘 `gz` 主前馈始终使用完整比例 `1.0`，不再对 `PIVOT` 单独降权。

F103 底盘速度恢复使用本项目原标定：

```text
wheel_diameter = 0.067 m
wheel_radius   = 0.0335 m
wheel_circumference = π × 0.067 m
counts_per_wheel_rev = 13 × 30 × 4 = 1560
```

左右轮使用统一 6.7 cm 轮径换算位移，再取平均作为 H723 使用的车体前进速度。

F103 的预转弯距离、速度差分和转弯里程直接使用编码器累计计数换算为米，
不再经过 `Motor_GetDistanceCm()` 的厘米整数量化。

### 4.3 Yaw 速度链

Yaw 使用位置环与速度环串联：

```text
position_rate
  = clip(8.0 × yaw_error, ±40°/s)

track_rate
  = AlphaBeta_residual_rate
  + geometry_rate

rate_target
  = track_rate + position_rate

rate_error
  = rate_target - gyro_z

rate_integral
  += 40.0 × rate_error × dt

yaw_rpm
  = (track_rate + position_rate
     - (chassis_gz + chassis_lead)
     + 7.0 × rate_error
     + rate_integral) / 6
```

参考工程的活动链路直接使用完整的目标估计速率，不再拆成“几何前馈 + 受限
AlphaBeta 残余前馈”，也不再增加编码器速度小修正。

AlphaBeta 位置预测始终保留。`APPROACH/PIVOT/EXIT` 时只把 AlphaBeta
残余速度清零、继续更新目标位置；三个转弯阶段全部结束后通过 `300 ms`
settle 窗口恢复速度学习。
已知的车速几何速率和底盘 `gz` 前馈仍持续参与，不会被 settle 清零。

限制：

```text
位置角速度 ±40°/s
AlphaBeta 残差速度 ±90°/s
速度积分 ±60°/s
最终输出 ±50 rpm
不增加额外的 2 s 启动输出斜坡
```

速度积分只在视觉目标有效且角度误差小于 `3°` 时累积，并在输出同方向
饱和时阻止继续绕积分。

## 5. Pitch 控制

目标世界俯仰由 AlphaBeta 位置直接给出，不再经过额外的 `pitch_target_guard`
或恢复轨迹。车辆前进还提供额外的俯仰角速度输入：

```text
pitch_vehicle_rate
  = h × v_lead × cos(phi) / target_range² × 57.29578

h = -0.182 m
```

```text
pitch_motor_target
  = world_pitch_target - current_platform_pitch
```

控制与参考工程 `pid_calc()` 一致：

```text
error = pitch_motor_target - pitch_encoder
P = 7.0 × error
I = 0.02 × integral
D = 0.10 × (error - previous_error)

position_pid = P + I + D

pitch_rpm
  = position_pid
  + pitch_target_rate / 6
  - 1.5 × gyro_y / 6
```

最终限幅为 ±50 rpm。Pitch 位置反馈只使用电机编码器，IMU 负责提供平台俯仰扰动和目标预测。

Pitch 的参考实现是“每拍误差差值与 Kd 相乘”，不是通用
`PID_Update()` 中的 `误差变化/dt`。本工程已按 500 Hz 控制周期执行。

## 6. F103 底盘遥测

H723 使用 UART7，`115200 8N1` 接收 F103 的固定 22 字节帧：

| 偏移 | 字段 | 说明 |
| --- | --- | --- |
| 0 | `AA 55` | 帧头 |
| 2 | `version=5` | 协议版本 |
| 3 | `type=0x31` | 底盘状态帧 |
| 4 | `seq` | 小端 16 位序号 |
| 6 | `phase` | 0 直行、1 准备转弯、2 转弯、3 新直边抓取/出弯、4 故障 |
| 7 | `turn_dir` | `+1` 左、`-1` 右、`0` 无效 |
| 8 | `flags` | bit0 控制有效、bit3 故障 |
| 9 | `distance_zone` | 0 未知、1 近边、2 远边、3 过渡 |
| 10 | `speed_mm_s` | 小端 int16，实测车体速度 |
| 12 | `yaw_rate_dps_x10` | 小端 int16，底盘 `gyro_z × 10` |
| 14 | `corner_count` | F103 已完成直角弯的绝对计数 |
| 15 | reserved | 当前为 0 |
| 16 | `sample_ms` | F103 采样时刻，小端 uint32 |
| 20 | `crc16` | 小端 CRC16-CCITT-FALSE，覆盖 0~19 |

CRC 参数为 `poly=0x1021, init=0xFFFF`，测试向量 `"123456789"` 的结果为
`0x29B1`。H723 对坏帧、错误版本、错误类型和超时帧全部拒绝。

`sample_ms` 在 F103 生成同一帧 phase、速度、gz 和转角的临界区内读取。
H723 记录本板接收 tick，并持续维护两板 tick 的最小观测差：

```text
raw_age_ms = H723_receive_tick - F103_sample_ms
relative_age_ms = raw_age_ms - min(raw_age_ms)
```

由于两板时钟独立，`min(raw_age_ms)` 包含未知固定时钟偏置和最快路径耗时；
因此 `relative_age_ms` 能可靠反映额外延迟和尖峰，但不能单独给出绝对单程
物理延迟。绝对延迟仍需双板时钟同步或 ping/pong 往返测量。

H723 的 UART7 PE7/PE8 使用 `AF7`，备用引脚组才使用 `AF11`。11.4 回退版
误把 PE7/PE8 配为 `AF11`，会表现为底盘完全收不到数据；现已恢复为 `AF7`。

路线相位现在由 F103 产生并直接发送：

```text
corner_count % 4 = 0 -> 近边
corner_count % 4 = 2 -> 远边
corner_count % 4 = 1/3 -> 过渡段
```

H723 不再通过 `PIVOT -> EXIT/TRACK` 猜转角计数。`corner_count` 在每次
`REACQUIRE` 连续3帧确认新直边后加一。`phase` 仍负责描述当前转弯
过程，`distance_zone` 负责描述当前路段远近属性。

## 7. 视觉丢失与转弯稳定

显式 `404` 帧表示当前帧没有有效目标，但 H723 不立刻清空 AlphaBeta 状态：

1. 已有跟踪器继续按最后一次速度和已知车辆运动量外推，最多 `450 ms`；
2. 距最后有效测量超过 `500 ms` 后停止该跟踪器，目标停在最后一次预测值；
3. 不增加锁存位置后的偏离限幅、恢复轨迹、3 帧重捕获或 Pitch guard；
4. 显式 404 连续达到 `500 ms` 后，通信层切回 `STAB` 并重新锁零；
5. 真正连续 `300 ms` 收不到任何 K230 字节时视为通信断流并切 `STAB`。

转弯时不关闭视觉，也不冻结 Yaw 目标。`APPROACH/PIVOT/EXIT` 期间
AlphaBeta 只更新位置、把残余学习速度清零；三个转弯阶段全部结束后再保持
`300 ms` 不学习速度。
这与参考工程 `turning + track_settle_ms` 的处理一致。转弯期间完整的底盘
`gz` 前馈、`0.10 s` 角加速度超前和车速几何前馈继续工作。

F103 的转角优先使用 MPU6050 实际角速度积分；IMU 仅允许 `50 ms` 短时
失效，期间才降级为高精度轮速差推算。累计达到 `80°` 后进入
`TRACK_REACQUIRE`，继续保持 `0.14 m/s` 转弯并读取新直边。

`REACQUIRE` 使用参考工程条件：

```text
target_w = clamp(-0.020 × line_error_mm - 1.50 × next_edge_error,
                 ±1.50 rad/s)
```

连续3个新灰度帧满足横线误差不超过 `1.5 × 11.14 mm`、新直边航向误差
不超过 `15°`、角速度小于 `0.35 rad/s` 后，才进入 `LINE` 并开始0.8秒
速度恢复。

F103 正式转弯恢复参考工程的角速度斜坡：

```text
remaining = π/2 - turn_angle - gyro_z × 0.20 s
target_w = min(v / 0.062, sqrt(2 × 8 × remaining))
body_w += clamp(target_w - body_w, ±8 × dt)
```

`body_w` 不再在进入 `TURN` 时直接跳到 `target_w`。入弯触发距离不变，
继续使用 `sensor_ahead=0.185 m`、`radius=0.062 m` 和已有的
`turn_lead = v × (0.20 + w_turn/(2×8))`；该提前量本来就覆盖角速度斜坡，
因此不额外移动入弯点，避免扩大实际转弯半径。

当前参数下 `w_turn=0.14/0.062≈2.258 rad/s`，斜坡时间约 `0.282 s`，
对应 `turn_lead≈0.0478 m`。

实车左右转弯完成后均观察到约 `0.020 m` 外扩，方向对称，因此增加
`turn_lead_extra=0.020 m`。预转弯剩余距离额外减去该值，使左右转弯都
提前约 `2 cm` 起弯；稳态 `radius=0.062 m`、`turn_v=0.14 m/s` 和左右轮
差速保持不变。

F103 直线部分恢复回退前 `ff71418` 的整套低速阻尼与滤波：

```text
Kp = 0.018
Kd = 0.004
Kh = 0.400
Ki = 0.010
Kg = 0.800

灰度误差滤波时间 = 35 ms
误差积分限幅 = 40 mm·s
Heading trim 时间 = 0.8 s
Heading trim 门限 = 1.0 × 探头间距
```

直线误差积分、小增益航向修正和 35 ms 位置滤波一起恢复。丢线时同时清空
位置滤波、微分和积分状态。当前 F103 遥测、路线转角接口和 `90°` 完成判据
继续保留。

起步和出弯继续使用速度斜坡：

```text
起步：0 → 0.29 m/s，1.2 s smoothstep
出弯：0.14 → 0.29 m/s，0.8 s 线性斜坡
```

斜坡期间 F103 上报 `phase=3 TURN_EXIT`，转完后保持 `turn_dir` 有效；
`0.80 s` 后自动回到 `phase=0 STRAIGHT`。出弯斜坡期间应用
`ff71418` 的增益缩放：

```text

Kd × 1.25
Ki × 0.25
Kh × 0.50
角速度限幅 = 0.80 rad/s
```
