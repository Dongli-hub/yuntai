# 标定流程与现场调试手册

---

## 一、上电前的物理检查（5 分钟能省 2 小时）

| 检查项 | 怎么做 | 不合格的表现 |
|---|---|---|
| 激光与相机是否同轴 | 打远处 3m 外的墙，看光斑是否落在画面中心附近 | 偏出画面 => 机械重装 |
| 相机能否看见 405nm | `python tools/check_laser.py` | 检出率 0 => IR-cut 滤掉了，走光轴点兜底 |
| 相机是否拧紧 | 手轻推镜头，画面不应有位移 | 松动会让光轴点漂移，标定全废 |
| 串口交叉接线 | TX→RX、RX→TX、共地 | 收不到 `GIMBAL_STATE`，程序卡在 BOOT_WAIT |
| 波特率一致 | 两边都 921600（或都 115200） | `crc_err` 持续增长 |
| 相机曝光 | 手动 1/500 ~ 1/2000 试 | 光斑过曝成一坨 / 靶纸太暗 |

## 二、三步标定

### 第 1 步：相机内参（装镜头后做一次）

```bash
python tools/calib_intrinsic.py --source 0 --cols 9 --rows 6 --square 25
# SPACE 采集（12 张以上，棋盘放在靶面附近不同位置/角度），C 计算并保存
python main.py run --extra-config configs/intrinsic.yaml
```

* 输出里会打印**水平视场角**和**建议的扫描步长**（视场 × 2/3），
  把它填进 `configs/default.yaml` 的 `acquire.step_deg`
* RMS > 1.0px 说明棋盘不平或图像有运动模糊，重做
* 没条件标定也能跑：把 fx 按"分辨率宽度 / (2·tan(视场/2))"估一个即可。
  fx 偏 20% 只影响收敛速度，不影响最终精度（因为环里有积分）

### 第 2 步：光轴点 + 偏置符号（每次拆装后做一次）

```bash
python tools/calib_boresight.py --port-gimbal /dev/ttyUSB0 --source 0
python main.py run --extra-config configs/boresight.yaml
```

它做三件事：

1. **光轴点** `boresight_uv`：激光光斑在图像里的固定位置（同轴装配的必然结果）。
   实测 3s 取中位数。这是**发挥部分 3 激光门控的前提**。
2. **`sign_yaw` / `sign_pitch`**：给 6° 偏置，看**靶心**往哪边跑。
   * 符号判错 => 云台"越修越偏"，直接失控，这一步绝对不能省
3. **实测每度多少像素**：应约等于 `fx·π/180`。差 25% 以上说明 fx 标定
   或分辨率设置有问题

> **为什么判符号必须看靶心、不能看光斑**：
> 光斑是刚性固定在图像上的，转云台它**不动**；
> 只有世界里的靶心会动。这正是本方案的核心原理（见设计大纲 §1.1）。

### 第 2.5 步：光斑-距离表（激光装在镜头下方时必须做）

```bash
python tools/calib_boresight_table.py --source 0 --port /dev/ttyS1
# 按提示把靶纸依次摆到 0.5 / 0.8 / 1.2 / 1.6 m，每个距离按一次回车
```

为什么需要它：激光与相机**不同轴**（你的激光在镜头下方），光斑在画面里的
像素位置随靶纸距离漂移：

```
光斑方向角 ≈ 两轴夹角 alpha + 两轴平移 d / 距离 L
```

所以"标定一个固定像素点"只在标定距离上准：0.8m 标的点，到 1.5m 可能偏
几十像素（换算到靶面上就是几厘米）。正确做法是标 2~3 个距离点，
运行时用**靶纸单应矩阵算出的距离**去查表插值 —— 不需要额外测距模块。

这张表只在光斑检不到的时候用（能检到就以实测光斑为准，那是最准的）。
结果写进 `configs/boresight.yaml`，程序启动自动叠加。

### 第 3 步：看着画面调检测阈值

```bash
python tools/view_detect.py --source 0            # 有显示器
python tools/view_detect.py --source 0 --snapshot out/dbg --interval 1.0   # 无显示器
```

看三件事：

* 绿色四边形是否**贴着黑胶带外沿**（说明黑框检测正确）
* 右上角小图（透视矫正后的靶面）里五条红圈是否都在
* 粉色圈（激光）是否稳定停在固定位置不动

快捷键：`r` 切换 `require_red`（用空白 A4 调试时关掉）、
`b` 切蓝优势门限、`s` 存图。

## 三、先在 PC 上跑通，再上真机

```bash
python main.py sim --duration 26 --laps 1 --start-car          # 基本要求 + 发挥(1)(2)
python main.py sim --duration 27 --laps 1 --draw --start-car   # 发挥(3) 画圆
python tests/run_all.py                                        # 21 项自测
```

仿真会输出一份 CSV（`out/aim_*.csv`），里面每一帧都有
靶心像素、光斑像素、误差、偏置、云台实际角、小车段/进度、
以及**仿真真值**（激光落点到靶心的真实毫米距离 `sim_miss_mm`、
到 r=6cm 红圈的距离 `sim_d2_mm`）。

**这是最快的调参路径**：仿真里确认 kp 不振荡、拐角尖峰可接受，
再到真机上只做微调。

## 四、真机联调顺序（严格按这个顺序，别跳）

```
1. 只开云台链路，不开激光：
   python main.py run --no-laser --no-car
   期望：BOOT_WAIT -> ACQUIRE -> LOCK（★ 锁定靶心）
   卡在 BOOT_WAIT => 收不到 GIMBAL_STATE，查串口/波特率/接线

2. 开激光，看光斑：
   python tools/check_laser.py --source 0 --port /dev/ttyUSB0 --save
   期望：检出率 > 80%

3. 标定：
   python tools/calib_boresight.py --port-gimbal /dev/ttyUSB0 --source 0

4. 完整瞄准（基本要求 2/3）：
   python main.py run --duration 15 --budget 4
   期望：★ 锁定靶心 用时 < 2s（不含 H723 启动则 < 1.5s）

5. 加小车链路：
   python main.py run --duration 30 --laps 1 --start-car
   期望：每过一个拐角打印"拐角 N -> 增强瞄准 450ms"

6. 画圆：
   python main.py run --duration 30 --laps 1 --draw --start-car
   期望：起跑前打印"画圆起点就位（误差 X px）"
```

## 五、故障速查表

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| 一直停在 `BOOT_WAIT` | 收不到 `GIMBAL_STATE` | 查接线（TX/RX 交叉、共地）、波特率、H723 是否在发 |
| 一直停在 `ACQUIRE` 扫不到靶 | 相机没对准/曝光不对/阈值不对 | 先 `view_detect.py` 看能不能检出；再查 `acquire.step_deg` 是否大于视场 |
| 找到靶但云台**越修越偏**、最后飞出画面 | `sign_yaw/sign_pitch` 反了 | 重跑 `calib_boresight.py`，或手动把配置里的符号取反 |
| 云台持续小幅抖动 | `control.kp` 太大 | 每次减 0.05；参考极限 `2·sin(45°/D)` |
| 跟随总是"慢半拍"、拐角误差大 | `control.lead_s` 太小 | 从 0.045 加到 0.06~0.07；过大反而会振 |
| 拐角处误差尖峰特别大 | 拐角事件没收到 | 看有没有"拐角 N"日志；查 RCT6 是否发 `0xA1` |
| 画圆相位不动 / 停在 1/4 圈 | 没收到拐角事件 | `draw.phase_source` 临时改 `time` 验证链路 |
| 画圆时靶心留下一个孤立的深斑 | 激光门控没开 | 确认 `draw.laser_gate: true` 且已标定 `boresight_uv` |
| 跑完一圈导线拧成麻花 | 云台绕线（物理必然） | 跑前/跑后各执行一次 `python main.py unwind`；长期方案是滑环（见风险 R2） |
| `crc_err` 不断增长 | 波特率不一致 / 线太长 / 没共地 | 降波特率到 115200 试；缩短线；确认共地 |
| 帧率只有 20~30fps | 分辨率太高 | 降到 960×540 或 640×480；`app.max_fps` 也可限速省 CPU |

## 五·补：真机性能调优（地瓜派 X3 实测记录）

第一次上真机时，帧率只有 **9fps** —— 而视觉伺服的稳定性和跟踪能力**直接由帧率决定**。
查下来是四个原因叠加，全部已修，最终 **48fps**：

| # | 问题 | 现象 | 原因 | 修法 |
|---|---|---|---|---|
| 1 | 相机跑在 YUYV 而不是 MJPG | 1280×720 只有 9fps | **V4L2 下"设分辨率"会重新协商管线，把先设的 FOURCC 冲掉** | 改成"先分辨率 → 再 FOURCC → 读回核对 → 最后帧率" |
| 2 | `buffer_size=1` | 帧率 50 → **17fps** | V4L2 只给 1 个缓冲就无法流水线采集 | `buffer_size` 改回 0（不碰驱动默认） |
| 3 | 全分辨率检测 | 检测要 **111ms/帧** | CPU 是瓶颈（不是相机） | 加 `camera.process_scale: 0.5`，在缩小图上做二值化+找四边形 |
| 4 | 矫正图太大 | warp 到 840×1188 | 红圈质心不需要那么高分辨率 | `warp_scale: 4.0 → 2.0` |

**优化结果**：

```
靶纸检测   89.5ms → 12.0ms
激光检测   21.7ms →  6.3ms
合计      111ms(9fps) → 18.3ms(50fps)
相机      YUYV 9fps → MJPG 50fps
闭环      9fps → 48fps
```

### 检查帧率的正确方法

```bash
# 相机到底能给多少帧（和我们的程序无关）
v4l2-ctl --list-formats-ext -d /dev/video0
# 程序启动时会打印"实际生效"的格式，和配置不一致会告警：
python3 main.py check --duration 5
```

> 启动日志里的 `相机实际生效: MJPG 1280x720 自报60fps` 这行一定要看。
> 如果显示的是 YUYV，帧率会差 6 倍，而且**不会报任何错**。

### 关于"红圈"在真机上的可靠性（重要）

```
靶纸离相机 0.8m，1280 宽 / 约 90° 视场 → fx ≈ 640px
   黑胶带 18mm → 成像约 14 像素   ✅ 糊了也能量出来
   红圈线宽 1mm → 成像约 0.8 像素  ❌ 比一个像素还细
```

所以真机上**不要把红圈当硬门槛**（`target.require_red: false`），
改由**黑胶带厚度校验**当主力判据（横竖分别量，都应在 0.4~1.8 倍标称值内）。

这个判据还能顺手排除场地里那条 1m 巡线黑方框 —— 它的线宽只占边长 1.8%，
被强行矫正成 A4 后量出来只有 0.13~0.35 倍，直接出局。

## 七、现场参数速查（只调这几个）

| 想解决什么 | 改哪个 | 方向 |
|---|---|---|
| 瞄准抖动 | `control.kp` | 减小（0.20 → 0.15） |
| 收敛太慢、2s 不够 | `control.kp` | 增大（0.20 → 0.28） |
| 运动时总落后 | `control.lead_s` | 增大（0.045 → 0.06） |
| 运动时来回摆 | `control.lead_s` | 减小到 0.02 |
| 拐角处尖峰大 | `control.kp_corner` / `corner_lead_scale` | 减小（0.30 → 0.20 / 0.35 → 0.15） |
| 扫描太慢 | `acquire.step_deg` / `dwell_ms` | 步长加大到视场 3/4；停留降到 50ms |
| 检不到靶 | `target.require_red` / `adaptive_block` | 先用空白 A4 调试时关 require_red |
| 检不到光斑 | `laser.b_minus_others` / `b_min` | 降到 20 / 100 |
| 画圆同步超差 | `draw.phase_offset` | 微调起点；确认拐角事件在发 |
