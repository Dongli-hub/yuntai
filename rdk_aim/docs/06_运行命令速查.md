## 1. 每次上电后的固定顺序（直接整段复制）

> **先给 H723 上电**，然后**等 4 秒**再碰云台
> （那 2 秒在采陀螺零偏，晃了会标定不准）。
> 判断云台起没起来：用手掰一下，**变硬了就是好了**。

```bash
cd /root/e_aim

# ① 串口在不在（ttyS2/3/4/6/7 会打不开，那是设备树没使能，正常）
python3 main.py ports

# ② H723 在不在说话（应该看到它的启动日志 + 云台已就绪）
python3 main.py ping --port /dev/ttyS1

# ③ 相机 + 靶纸自检（对着靶纸跑，应该看到靶纸检出率 100%）
python3 main.py check --duration 6

# ④ 激光光斑自检（激光常亮，不用加 --laser）
python3 tools/check_laser.py --port /dev/ttyS1 --source 0

# ⑤ 标定：光轴点 + 偏置方向符号（拆装过就要重跑）
python3 tools/calib_boresight.py --port-gimbal /dev/ttyS1 --source 0

# ⑤.5 标定：光斑位置随距离的变化（激光在镜头下方，这个必须做）
#     把靶纸依次摆到 0.5 / 0.8 / 1.2 / 1.6 m，每个距离按一次回车
python3 tools/calib_boresight_table.py --source 0 --port /dev/ttyS1

# ⑥ 正式瞄准（--budget 是赛题时间指标，2 或 4）
python3 main.py run --duration 20 --budget 4

# ⑦ 跑完一轮解绕（跑过行驶模式才需要）
python3 main.py unwind --duration 10
```

## 2. 每条命令正常长什么样

### ② `ping` —— 确认链路

**正常**：

```
H723 [GYRO] bias(dps) x=0.12 y=-0.34 z=1.02 n=900
H723 [REF] yaw=123.45 pitch_motor=-87.65
H723 [DBG] P p=-87.6 t=-87.6 o=0 | Y o=-1 | off=0.0 0.0 | fb=6ms
遥测: state=5 fault=0 yaw=0.01 pitch=0.14 roll=0.59 motor=(0.2,177.5) flags=0x17
链路 OK。云台已就绪
```

**要看的四个地方**：

| 字段 | 正常值 | 不正常说明什么 |
|---|---|---|
| `fault` | `0` | `1` = 俯仰编码器反馈断了 |
| `flags` | 含 `0x04` | 没 `0x04` = 编码器没在线 |
| `motor=(x, y)` | 两个都不是 0 | 是 `(0.0, 0.0)` = CAN 反馈没上来 |
| `[DBG]` 数字 | 都有具体数值 | 全空 = 格式化出问题 |
| `[DBG] fb=` | **小于 15ms** | 几十毫秒 = 俯仰位置反馈太旧，位置环等效延迟变大，掰一下就会抖（固件已改成每 20ms 主动查一次） |

### ③ `check` —— 确认视觉

**正常**（对着靶纸）：

```
相机实际生效: MJPG 1280x720 自报60fps      ← 必须是 MJPG，是 YUYV 就慢 6 倍
帧=49 靶纸=49(100%) 光斑=48 ...
```

### ⑥ `run` —— 正式瞄准

**正常**：

```
[  0.2s][ACQUIRE] 扫描 1/21 -> (0°, 0°)
[  0.5s][LOCK   ] 状态 ACQUIRE -> LOCK <- 检出靶纸 conf=0.82
[  1.3s][LOCK   ] ★ 锁定靶心：用时 1.312s，误差 3.24px
```

每 5 秒一条的 `[STAT]` 用来看链路质量：

```
H723 [STAT] rx=NNN crc=0 ovf=0 rsv=0 txdrop=0
```
`crc` / `ovf` 一直涨 = 波特率或接线有问题。

## 4. 结果文件在哪、怎么拿回电脑

每次运行都会生成 `/root/e_aim/out/aim_<时间戳>.csv`，
里面**每一帧**都有：靶心像素、光斑像素、误差、云台偏置、遥测状态。

```bash
ls -lt /root/e_aim/out/ | head -3

# 直接统计最新那份的误差
python3 -c "
import csv,glob,os
fs=sorted(glob.glob('/root/e_aim/out/*.csv'),key=os.path.getmtime)
rows=list(csv.DictReader(open(fs[-1])))
e=[float(r['err_norm']) for r in rows if r['err_norm']]
e.sort()
print('样本 %d  中位误差 %.2f px  90分位 %.2f px  最大 %.2f px'
      % (len(e), e[len(e)//2], e[int(len(e)*0.9)], e[-1]))
"
```

**拿回电脑**（在 Windows 的 PowerShell 里跑，注意用正斜杠）：

```powershell
scp -r 192.168.43.10:/root/e_aim/out D:/STM32/STM32projects/yuntai2/rdk_aim/out/rdk
```

## 5.5 俯仰被手掰一下就抖？用在线调参定位（不用重新烧写）

现象：上电后俯仰电机变硬，用手掰一下，松手后它开始前后抖动 /
幅度慢慢变大；用手扶住反而稳住。这说明**环路里缺阻尼**，
但这个"缺阻尼"**不是陀螺前馈造成的** —— IMU 装在俯仰电机下面，
掰俯仰轴时陀螺根本不动，前馈不参与。所以先查位置环：

| 抖动频率 | 病因 | 怎么办 |
|---|---|---|
| > 3 Hz | 增益型自激：KP 相对驱动器速度环的延迟太大 | `p`（KP=8 KI=20） |
| < 2 Hz | 积分/摩擦型极限环：KI 太大 / 机构间隙 | `k 8 15 0.1` |

前馈符号是另一件事，必须**倾底座**（IMU 看得见的运动）才测得出来：

| 相关系数（陀螺角速度 vs 电机角速度） | 含义 |
|---|---|
| 负 | 电机在反向补，前馈符号正确 |
| 正 | 电机跟着一起动，前馈符号反了，按 `-` / `+` 换 |

工具会**在线改参数**（H723 立刻生效、掉电恢复默认），
并且自动把你"掰一下松手"之后的曲线算成两个数字：
第 2 秒和第 3 秒的峰峰值之比 —— 小于 0.8 是收敛，大于 1.15 是发散。

```bash
cd /root/e_aim
python3 tools/tune_pitch.py --port /dev/ttyS1

# 进菜单后按这个顺序来（每次只改一项）：
#   t        -> 先掰一下俯仰轴，看现在的抖动频率和收敛/发散
#   p        -> 一键套用安全预设 KP=8 KI=20（会紧接着自动掰一下测试）
#   k 8 15 0.1  -> 低频抖（<2Hz）时再降 KI
#   f        -> 前馈极性检查：倾底座，工具算相关系数（负=对）
#   c 1      -> 打开"平台俯仰补偿"（云台整体低头/抬头时镜头自己找回来）
#               验证：慢慢把底座倾斜 10°，靶面光斑基本不动 = 符号对
#   -        -> 前馈符号取 -1（保持安全增益）
#   +        -> 前馈符号取 +1
#   0        -> 把前馈整个关掉（gain=0）
#   d        -> 打印当前参数
#   q        -> 退出（自动切回 STAB）
```

> 前提：H723 上必须是**带 0x15 PARAM 的固件**。
> 工具启动时会自己检查 —— 如果它说"没有回 [PARAM]"，就是板上还是旧固件，
> 先在 CubeIDE 里重新编译烧写。

调出满意的数值后，把它写回 `Core/Src/yuntai_task.c` 里对应的 `#define`
（`PITCH_FF_SIGN` / `PITCH_FF_RPM_PER_RADS` / `PITCH_KP` …）再烧一次固化。
在线参数掉电就没了。

### 5.6 云台整体低头/抬头时镜头不找回来

现象：把云台（或整车）整体前后倾，**俯仰电机一动不动**，镜头跟着一起低下去。

这不是参数调坏了，而是位置环的"天生盲区"：

> 俯仰位置环的反馈是**电机自己的编码器**，量的是"电机相对底座"的角度。
> 底座整体倾斜时这个角压根不变 → 位置环误差为 0 → 电机不动。

所以必须由 IMU 告诉它"世界倾斜了多少"，再把俯仰目标反向挪同样的角度 ——
这就是**平台俯仰补偿**（老固件里有，重写时默认关掉过，现在已恢复默认打开）。
它和陀螺前馈的分工是：

| 谁 | 管什么 | 特点 |
|---|---|---|
| 陀螺前馈 | 正在倾斜的那一瞬间 | 快，但没有绝对基准 |
| 平台俯仰补偿 | 倾斜之后的持续角度 | 慢，有绝对基准 |

```bash
# 看当前补偿量：[DBG] 行里的 c= 就是它（单位度）
# 在线开关/换符号：
#   c 0   -> 关闭
#   c 1   -> 打开（默认；老固件验证过的符号）
#   c -1  -> 打开但符号取反
```

验证方法：把握着云台底座慢慢前后倾 10°，盯着靶面光斑 ——
**基本不动**说明符号对；**比关闭时动得更大**说明符号反了，换另外一个。
符号规矩：`补偿符号 = -前馈符号`（老固件是 FF=-1、COMP=+1）。

## 6. 激光常亮要注意的三件事

1. **安全**：现在一上电激光就亮，调试时别让光斑对着人或反光面，
   建议让它打在靶纸上。

2. **不用加 `--laser` 参数**：那个参数是"通过协议请求点亮激光"，
   现在激光本来就亮，加了没有区别。

3. **发挥部分(3) 画圆暂时做不了**：题目要求"起跑前关激光"，
   否则靶心会留下一个孤立深斑 + 一条径向拖痕，D2 直接超差。
   这需要多接一根 GPIO 控制线（H723 的 PC4），到时候：
   - 固件：`LASER_GPIO_ENABLE` 改 1、`LASER_ALWAYS_ON` 改 0
   - 配置：`laser.always_on` 改 false
