# 串口通信协议（逐字节定义）

两条链路共用同一套帧格式，只有消息 ID 不同：

| 链路 | 谁连谁 | 波特率 | 方向 |
|---|---|---|---|
| 云台链路 | 地瓜派 ↔ H723（USART1） | **115200** | 双向 |
| 小车链路 | 地瓜派 ↔ RCT6（新增一路串口） | 115200 | 双向 |

> **接线**：交叉接（地瓜派 TX → MCU RX，地瓜派 RX → MCU TX），共地。
> **地瓜派 ↔ H723 只需要 3 根线：TX / RX / GND**（两边各自供电，不需要接电源线）。
> 只接 TX/RX 两根、不共地是一定不通的 —— 这是最常见的坑。
> 地瓜派侧是 3.3V TTL，H723/RCT6 也是 3.3V，可以直接接；
> **不要接 5V**。USB 转串口模块请用 3.3V 电平的那种。

> **为什么用 115200 而不是更快的波特率**：
> 实测带宽需求只有约 2.8KB/s（下行 AIM 11 字节 × 100Hz + 上行遥测 28 字节 × 50Hz），
> 115200 有 3 倍余量；而波特率越高、对线长和干扰越敏感。
> 现场接线是杜邦线，115200 明显更稳。

## 一、帧格式

```
 偏移  长度  字段        说明
  0     1    0xAA        帧头 1
  1     1    0x55        帧头 2
  2     1    msg_id      消息类型
  3     1    seq         序号 0~255，只用来看丢帧，不参与校验逻辑
  4     1    len         payload 长度（不含头、不含 CRC），0~240
  5     len  payload     负载
  5+len 2    crc16       小端；CRC16/Modbus，覆盖 msg_id..payload
```

**CRC16/Modbus 参数**：

```
初值  0xFFFF
多项式 0xA001（即 0x8005 反射形式）
输入/输出不反转；结果直接当 16 位小端写入
自检：crc16("123456789") == 0x4B37
```

为什么不用 ASCII 行协议：

* 100Hz × 每次 AIM，ASCII 至少 30 字节；二进制只要 11 字节
* CRC16 能可靠发现干扰导致的错帧；行协议只能靠字符集判断，不可靠
* 长度字段让解析器天然抗粘包/断包

解析器必须做**重同步**：找不到 0xAA 0x55 就丢弃前面的字节；
长度非法（>240）也要丢掉当前"假帧头"继续找。参考实现见第五节。

## 二、地瓜派 → H723

### 0x10 `AIM` —— 瞄准偏置（核心指令，100Hz）

| 偏移 | 类型 | 名称 | 说明 |
|---|---|---|---|
| 0 | int16 | yaw_deg_x100 | 偏航偏置，单位 0.01°（有符号小端） |
| 2 | int16 | pitch_deg_x100 | 俯仰偏置，单位 0.01° |
| 4 | uint8 | flags | 见下 |
| 5 | uint8 | quality | 0~255 跟踪质量（越大越好，只用于显示/联锁） |

flags 位：

| 位 | 名称 | 含义 |
|---|---|---|
| 0 | LASER_ON | 请求点亮激光 |
| 1 | AIM_VALID | 本帧视觉有效（H723 可用来决定是否更新偏置） |
| 2 | BOOST | 拐角加强中 |
| 3 | DRAWING | 正在画圆 |
| 4 | LOCKED | 已锁定靶心 |

**长度固定 6 字节**。

> **H723 侧必须实现的关键语义**：
> `yaw 目标 = yaw 上电锁定值 + yaw_deg_x100/100`
> `俯仰目标 = 俯仰基准 + pitch_deg_x100/100`
> 也就是说，**偏置是加在稳定基准上的**，稳定能力完全保留。
> 千万不要把偏置直接当成目标角去覆盖基准，否则小车一动云台就丢稳。

### 0x11 `MODE` —— 工作模式

| 偏移 | 类型 | 名称 | 说明 |
|---|---|---|---|
| 0 | uint8 | mode | 0=IDLE 1=STAB 2=AIM 3=UNWIND 4=ESTOP |
| 1 | uint8 | arg | 备用 |

模式语义：

| mode | 行为 |
|---|---|
| IDLE | 不使能、不控制（电机自由，可手掰） |
| STAB | 只做姿态稳定，忽略偏置，激光关闭。**掉线/异常时的安全模式** |
| AIM | 稳定 + 应用偏置（正常工作模式） |
| UNWIND | 解绕：把相对偏航角以 `0x14` 指定的速度转回 0，**激光必须关闭** |
| ESTOP | 急停：停止下发速度指令 |

### 0x12 `HEARTBEAT_G` —— 心跳（payload 空）

### 0x13 `SET_ZERO` —— 把当前朝向记为偏置零点（payload 空）

收到后：把当前的绝对方位/俯仰记为新的基准，并把偏置清零。
地瓜派在进入 AIM 之前会发一次。

### 0x14 `UNWIND` —— 解绕速度

| 偏移 | 类型 | 名称 | 说明 |
|---|---|---|---|
| 0 | uint16 | speed_dps_x10 | 解绕角速度，单位 0.1°/s（默认 30.0°/s → 300） |

### 0x15 `PARAM` —— 运行时就地调参（**只用于现场排障，不属于比赛流程**）

| 偏移 | 类型 | 名称 | 说明 |
|---|---|---|---|
| 0 | uint8 | param_id | 见下表 |
| 1 | int16 | value | **真实值 × 100**（15.00 → 1500，-1.00 → -100） |

H723 收到后回 `ACK(msg_id=0x15, code=param_id)`，并额外发一条
`TEXT` 形如 `[PARAM] id=5 <- 8.00 OK`，方便在终端里确认"确实生效了"。

| param_id | 名称 | 单位 | 固件内限幅 |
|---|---|---|---|
| 0x00 | DUMP | — | 不改任何东西，只回 4 行当前参数 |
| 0x01 | YAW_FF_SIGN | ±1 | — |
| 0x02 | YAW_FF_GAIN | rpm/(rad/s) | 0 ~ 200 |
| 0x03 | PITCH_FF_SIGN | ±1 | — |
| 0x04 | PITCH_FF_GAIN | rpm/(rad/s) | 0 ~ 60（0 = 关掉前馈） |
| 0x05 | PITCH_KP | rpm/deg | 0 ~ 40 |
| 0x06 | PITCH_KI | rpm/(deg·s) | 0 ~ 200 |
| 0x07 | PITCH_KD | rpm/(deg/s) | 0 ~ 5 |
| 0x08 | PITCH_ILIM | — | 0 ~ 5 |
| 0x09 | PITCH_OUT_RPM | rpm | 5 ~ 300 |
| 0x0A | PITCH_PLAT_SIGN | ±1 | 0 = 关；±1 = 开并定方向（默认 +1，与前馈符号相反） |

三条必须知道的规矩：

1. **参数只存在 RAM 里，重新上电恢复代码里的默认值。** 这是故意的：
   避免"上次调歪的值被记住"，让每次上电的状态都是已知的。
   调好后要把最终数值写回 `yuntai_task.c` 的 `#define` 再烧一次固化。
2. **改前馈符号 / 前馈增益 / PID 三个系数时，H723 会顺手 `PID_Reset`。**
   否则积分项会带着"上一个方向"的记忆继续推，瞬时长出一个大输出。
3. 这条消息只在 STAB/AIM 下调试时用，正式跑之前记得把参数恢复默认
   （`d` 看一眼，或者干脆重新上电）。

## 三、H723 → 地瓜派

### 0x90 `GIMBAL_STATE` —— 状态遥测（50Hz，固定 **21** 字节）

| 偏移 | 类型 | 名称 | 单位 |
|---|---|---|---|
| 0 | uint8 | state | 启动状态机当前状态（与固件里那 6 个状态一致） |
| 1 | uint8 | fault | 故障码，0=正常 |
| 2 | int16 | imu_yaw_x100 | 度 ×100 |
| 4 | int16 | imu_pitch_x100 | 度 ×100 |
| 6 | int16 | imu_roll_x100 | 度 ×100 |
| 8 | int16 | yaw_motor_x100 | 相对车身的偏航电机角，度 ×100（**绕线监视就靠它**） |
| 10 | int16 | pitch_motor_x100 | 俯仰电机角，度 ×100 |
| 12 | int16 | gyro_y_x100 | 度/秒 ×100 |
| 14 | int16 | gyro_z_x100 | 度/秒 ×100 |
| 16 | uint8 | flags | 见下 |
| 17 | uint32 | uptime_ms | 上电毫秒 |

flags 位：

| 位 | 名称 | 含义 |
|---|---|---|
| 0 | CLOSED_LOOP | 已进入闭环使能 |
| 1 | SPEED_MODE | 驱动器已是速度模式 |
| 2 | ENCODER_OK | 俯仰编码器反馈正常 |
| 3 | LASER_ON | 激光当前实际是开着的 |
| 4 | READY | **启动流程已走完、可以接受偏置**（上位机就该等这一位） |

地瓜派用 **`READY` 位**判断"云台可以接受偏置了"，
**不要用 `state` 数值去比大小** —— `state` 是固件内部枚举，
状态机一改就会变（踩过：去掉一个 INIT 状态后 RUNNING 从 6 变 5，
上位机就一直卡在 `BOOT_WAIT`）。

**如果 READY 一直不来，地瓜派会停在 `BOOT_WAIT` 并打印日志**，
此时看 H723 发来的 TEXT 日志卡在哪一步即可。

### 0x91 `ACK` —— 指令应答

| 偏移 | 类型 | 名称 | 说明 |
|---|---|---|---|
| 0 | uint8 | ack_msg_id | 被应答的消息 ID |
| 1 | uint8 | code | 0=OK，非 0=拒绝（地瓜派会打印 WARN） |

### 0x92 `VERSION` —— 版本字符串（payload 是 ASCII）

### 0x93 `TEXT` —— 调试文本（H723 → 地瓜派）

payload 是一段 ASCII/UTF-8 文本（最长 60 字节），地瓜派收到后直接打印成
`[H723] xxx`。

**为什么要有这条消息**：H723 的 USART1 本来就是 printf 调试口，
改造后变成二进制协议流，如果继续直接 printf 会把帧冲乱（现象是上位机
crc_err 暴涨、时好时坏）。把文本包成帧发出去以后，
"每一步都看得见"的调试习惯完全保留，而且不会破坏协议。

上电时按顺序应当看到（缺哪条就说明卡在哪一步）：

```
[H723] === YunTai Start ===
[H723] [BMI088] try #1 ...
[H723] [BMI088] result=0
[H723] [BMI088] OK -> motor boot delay
[H723] [MOTOR] boot delay done
[H723] [MOTOR] enter closed loop
[H723] [MOTOR] set speed mode
[H723] [IMU] locking reference ...
[H723] [REF] yaw_lock(deg)=xx.xx
[H723] [REF] pitch_motor(deg)=xx.xx
[H723] === STABILIZATION ACTIVE ===
```

运行期每 0.5s 一条状态行：

```
[H723] [DBG] P p=<俯仰编码器角> t=<俯仰目标> o=<俯仰指令rpm> | Y o=<偏航指令rpm> | off=<yaw偏置> <pitch偏置>
```

## 五、RCT6 → 地瓜派（小车上行）

### 0xA0 `CAR_STATE` —— 小车状态（建议 20Hz）

| 偏移 | 类型 | 名称 | 说明 |
|---|---|---|---|
| 0 | uint8 | state | bit0 = 正在行驶 |
| 1 | uint8 | lap_index | 当前是第几圈（从 1 开始） |
| 2 | uint8 | segment | 当前在第几段 0~3（0=A→B 1=B→D 2=D→C 3=C→A） |
| 3 | uint8 | progress | 本段进度 0~100 (%) |
| 4 | int16 | speed_mm_s | 当前速度 mm/s |
| 6 | uint16 | lap_time_ms | 单圈时间 ms |
| 8 | uint8 | gray_bits | 8 路灰度原始值（bit0=最左） |
| 9 | uint8 | flags | bit0 = 正在过拐角 |

`segment` + `progress` 是画圆相位同步的**最准来源**；
如果小车算不出进度，只发拐角事件也能满足指标（见第六节）。

### 0xA1 `CAR_EVENT` —— 事件（立即上报，不要等轮询）

| 偏移 | 类型 | 名称 | 说明 |
|---|---|---|---|
| 0 | uint8 | event | 1=CORNER 2=LAP_DONE 3=STARTED 4=STOPPED |
| 1 | uint8 | index | CORNER 时是拐角编号 0~3；LAP_DONE 时是圈号 |
| 2 | uint16 | value | 备用（例如 LAP_DONE 可带单圈时间 ms） |

**拐角事件是整个链路里最关键的信号**：地瓜派收到后在 0.45s 内
提高瞄准增益并把超前补偿压到 35%（理由见设计大纲 §4.5），
实测能把拐角处的落点偏差从 24mm 压到 8mm。

> 拐角判定建议：灰度模块出现"丢线/全黑"或"最外侧通道触发"，
> 并且此时车头已转过设定角度。**宁可晚 10ms，不要误报**：
> 误报会让云台在直道上突然变得激进。

## 六、时序与失效保护

```
地瓜派启动
   │ 每 200ms 发 MODE=STAB
   ▼
等到 GIMBAL_STATE 满足 state>=6 && CLOSED_LOOP && SPEED_MODE
   │ 发 SET_ZERO，然后 MODE=AIM
   ▼
扫描捕获 → 锁定 → 跟踪/画圆
   │ 每 10ms 发一帧 AIM（100Hz）
   ▼
退出/异常 → 发 MODE=STAB + AIM(激光关闭)
```

| 失效情形 | 检测方 | 动作 |
|---|---|---|
| 地瓜派 0.5s 没收到 `GIMBAL_STATE` | 地瓜派 | 打印 WARN，继续下发（可能是单向断线），但不做任何"看不见反馈就猛调"的动作 |
| H723 0.5s 没收到 `AIM` | **H723（已实现）** | 冻结偏置、切 STAB、关激光，并发一条 TEXT 说明 |
| H723 0.5s 没收到 `AIM`（画圆中） | H723 | 同上；画圆会中断，但不会失控 |
| RCT6 1s 没上报 | 地瓜派 | 打印 WARN；画圆相位退化为按 `draw.lap_time_s` 计时 |
| 串口 CRC 错帧率 >1% | 地瓜派 | 打印统计，提示检查波特率/线长/共地 |

### 模式与激光的对应关系（H723 侧已实现）

| 模式 | 偏航 | 俯仰 | 激光 |
|---|---|---|---|
| IDLE | 不发指令（电机自由） | 不发指令 | 关 |
| STAB | 保持上电朝向**不动**（忽略偏置） | 保持上电角度 | **关** |
| AIM | 保持朝向 + **叠加偏航偏置** | 保持角度 + **叠加俯仰偏置** | 由 `AIM.flags.bit0` 决定 |
| UNWIND | 用电机编码器把**相对偏航角转回 0** | 保持在锁定角度 | **关** |
| ESTOP | 两轴指令给 0 | 两轴指令给 0 | 关 |

> 关键点：**偏置只在 AIM 模式下生效**。所以"上位机掉线/不发了"会自动退化成
> STAB —— 云台仍然保持稳定，只是不再瞄准。这是设计上的安全降级。

## 七、STM32 侧参考实现（可直接搬到 H723 的 USART1）

```c
/* ---- CRC16/Modbus（与 Python 侧 crc16_modbus 完全一致）---- */
static const uint16_t crc_table[256] = { /* 由脚本生成，见下 */ };

uint16_t crc16_modbus(const uint8_t *data, uint16_t len)
{
    uint16_t crc = 0xFFFF;
    while (len--) crc = (crc >> 8) ^ crc_table[(crc ^ *data++) & 0xFF];
    return crc;
}

/* 表可以用下面这段一次性生成（跑一次打印出来贴进去）：
   for (i=0;i<256;i++){ crc=i; for(j=0;j<8;j++) crc = (crc&1)?((crc>>1)^0xA001):(crc>>1); }
*/

/* ---- 打包：注意全部小端，STM32 是小端，直接 memcpy 即可 ---- */
static void build_aim(uint8_t *out, int16_t yaw_x100, int16_t pitch_x100,
                      uint8_t flags, uint8_t quality, uint8_t seq)
{
    uint8_t body[6];
    body[0] = 0x10;                       /* msg_id */
    body[1] = seq;
    body[2] = 6;                          /* len */
    memcpy(&body[3], &yaw_x100, 2);
    memcpy(&body[5], &pitch_x100, 2);
    /* body[3..6] 已是 yaw,pitch 的小端字节 */
    ...
}

/* ---- 解析（在 USART1 空闲中断里把整块数据丢进环形缓冲，
        然后在主循环或 200Hz 任务里跑这个状态机）---- */
typedef struct {
    uint8_t  buf[256];
    uint16_t len;
    uint32_t crc_err, resync, frames;
} frame_parser_t;

void frame_feed(frame_parser_t *p, const uint8_t *data, uint16_t n)
{
    /* 1) 先把数据追加进 p->buf（注意溢出时丢最老的） */
    /* 2) while(1):
     *      find 0xAA 0x55        -> 找不到就丢弃前面的字节（resync++）
     *      len = buf[4]; len>240 -> 丢掉 2 字节假帧头，continue
     *      if (have < 5+len+2) break;
     *      crc16(buf+2, 3+len) == *(uint16_t*)(buf+5+len) ?
     *            dispatch(buf[2], buf+5, len) : crc_err++;
     *      丢掉这一整帧，continue;
     */
}
```

> **RX 中断建议**：H723 的 USART1 打开 `RXNE` + `IDLE` 中断，
> 或者 `HAL_UARTEx_ReceiveToIdle_DMA` 配合环形缓冲。
> **不要**在中断里做 CRC 和解析，丢进缓冲、在主循环里解析。

## 八、RCT6 侧需要新增的东西

RCT6 目前只用了 USART2（灰度模块，PA2/PA3）。给地瓜派需要再加一路：

| 选项 | 引脚 | 备注 |
|---|---|---|
| USART1 | PA9/PA10 | 最省事，但注意别和 SWD 复用冲突（PA13/14 才是 SWD，不冲突） |
| USART3 | PB10/PB11 | 也可以 |

固件里要做三件事：

1. `MX_USARTx_UART_Init()`：115200 8N1，开 RX 中断 + IDLE
2. 巡线状态机里加"段切换"检测 → 立即发 `0xA1 CAR_EVENT`（CORNER）
3. 每 50ms 发 `0xA0 CAR_STATE`

**先跑通第 2 条就能拿到最大的收益**（拐角增强），
第 2+3 条齐全才能做发挥部分(3) 的画圆同步。
