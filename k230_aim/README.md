# k230_aim —— K230 视觉瞄准程序

## 一、整机架构（谁负责什么）

```
        H723 (云台控制板)                        K230 (机载视觉)
   +---------------------------+          +---------------------------+
   | BMI088 姿态解算(Mahony)   |          | 相机取图 640x480/800x600  |
   | 双轴稳定环(速度环在驱动器)|          | 找 A4 靶纸 -> 靶心(u,v)   |
   | 视觉外环(新视觉帧现算偏置):|  UART    | 找激光光斑(u,v)           |
   |   像素误差 -> 角度偏置    | 115200   | 只上报像素坐标 + 状态     |
   |   目标角 = 上电锁定基准   |<-------->| 状态机 / 心跳 / 日志      |
   |          + 偏置           |          | 安全: 遥测断流 -> 发 STAB |
   | 激光 IO(仅 AIM 模式)      |          |                           |
   | 50Hz 遥测上报             |          |                           |
   +---------------------------+          +---------------------------+
        ^ 电机电源                              ^ 5V(从 H723 UART10 排针取)
```

**分工原则**：电机环要 200Hz+ 且不能被调度抖动污染 → 放 H723；
视觉 30~60Hz 算力需求大 → 放 K230；
**"像素误差 → 角度偏置"的外环放在 H723**：控制节拍仍是 1kHz，但视觉偏置
只在新视觉帧（AIM 头部 seq 变化）时更新一次，帧间保持；两者之间只传像素坐标。

| | K230（机载计算机） | H723（云台板） |
|---|---|---|
| 负责 | 相机取图、靶框/光斑检测、上报像素坐标、状态机、心跳、日志 | 姿态解算、双轴稳定、**视觉外环（像素→偏置，每视觉帧一次）**、激光 IO、遥测 |
| **不负责** | 不碰电机、不做姿态解算、不直接控激光硬件（只发请求） | **不做视觉**、不做路径规划 |
| 安全职责 | 遥测断流 → 主动发 STAB | 0.5s 收不到 AIM → 自动 STAB + 关激光；偏置限幅 ±190°/±20° |

### 通信（115200 8N1）

| 方向 | 消息 |
|---|---|
| K230 → H723 | `0x10 AIM`(**靶心/光斑像素 u16×4 + flags + 质量 + K×100, 30Hz 保持**)、`0x11 MODE`、`0x12 心跳`、`0x13 SET_ZERO`、`0x14 UNWIND`、`0x15 PARAM` |
| H723 → K230 | `0x90 遥测`(state/fault/姿态/电机角/陀螺/flags, 50Hz)、`0x91 ACK`、`0x93 TEXT 日志` |

AIM 头部 `seq` 是**视觉帧序号**：只有 K230 产生新检测结果时才递增；同一视觉帧
会重复发送多次（约 30Hz）用于喂 H723 看门狗，但 H723 只在 `seq` 变化时更新偏置。

AIM payload（12 字节）：`ut vt us vs`(u16×4 小端) + `flags` + `quality` +
`kx100`(i16 小端，像素/度 ×100)。最后 2 字节是**后加的**，为的是让 K 跟着
帧走（处理分辨率可切换，px/° 会变）：只发 10 字节的老上位机 / 只认 10 字节
的老固件都还能互通，这时 H723 用默认 K=7.8。`[VIS]` 行里的 `k=` 是它本帧
实际用的值 —— 换了分辨率却还是 7.80，就说明对面没带上 K。

**接线（最终方案，实测确定）**

| K230 | H723 |
|---|---|
| IO9 (TXD) | **USART1 端子 RX**（PA10） |
| IO10 (RXD) | **USART1 端子 TX**（PA9） |
| GND | GND |
| 5V | **UART10 排针第 1 脚 VCC** |

> 为什么数据不用 UART10/UART7：实测 UART7 排针数据线不通、UART10 的 RX(PE02)
> 收不到数据（都是板级硬件问题）；USART1 收发都验证通过，因此数据走它，
> 5V 从 UART10 的 VCC 取（那一脚本来的用途就是给上位机供电）。

### 上电时序

1. H723 上电：默认 **STAB**（自稳，激光关闭），状态机走到 RUNNING 后置 READY 位；
2. K230 启动：每 200ms 发心跳，等遥测里的 READY；
3. K230 发 `SET_ZERO`（把当前朝向记为偏置零点）→ `MODE = AIM`；
4. K230 约每 33ms 发 `AIM`（靶心/光斑像素 + LASER_ON/AIM_VALID 等 flags）；
   H723 只在新视觉帧序号时更新误差，然后在约 1.5 个视觉帧周期内连续修正，
   单帧累计最多 8°；偏置斜坡 80°/s；
5. 退出/异常：K230 发 `MODE = STAB`；若 K230 掉线，H723 自己 0.5s 后回 STAB。

### 靶纸检测判据（v12，改动原因写在 tools/vision_check.py 顶部）

| 版本 | 判据 | 结果 |
|---|---|---|
| v1~v3 | `find_rects` 找黑胶带框 | 3~9fps，框抖动 |
| v5 | 白纸块（无校验） | 用户否掉：白瓷砖地面会误检 |
| v6~v9 | 暗块找胶带 | 失败：胶带 L≈20 与木柜 L≈25~35 太接近，阴影连成一片 |

### 处理分辨率开关（2026-10-11 加，用户要求"试试提高分辨率"）

`main.py` / `tools/vision_check.py` 顶部的 `PROC_W` / `PROC_H` 是唯一开关：

| PROC_W×PROC_H | 像素量 | 实测/预计 | 什么时候用 |
|---|---|---|---|
| 640×480 | 1.00× | 实测 目标检测≈16ms/帧、整环 41fps | 稳、快（基准） |
| **800×600** | 1.56× | 预计检测≈25ms、≈30fps | 想知道"细一点能不能锁得更远更稳" |
| 480×360 | 0.56× | 预计≈9ms、≈60fps | 想上帧率（代价：远处细节少一半） |

改这一处就够：所有"像素"单位的常数（最小面积/长边/扫描余量/跟踪窗/死区/
跳变阈值/激光坐标/焦距/预瞄）都按 `S_SCALE = PROC_W/640` 自动缩放，
**不改判据的物理含义**。`PROC_W` 必须是 16 的倍数（ISP 只按 16 对齐）。

⚠ **显示画布固定 640x480，不要跟着改**：2026-10-11 实测这块板子的显示只吃
这个尺寸（800x600 直接报 `ST7701 unsupport 800x600`，VIRT 那条路在这版固件
上也不出画面）。所以 vision_check/main.py 都是"画布 640x480 + 用
`draw_image(x_scale/y_scale)` 把处理图像缩着画上去"——
你在 IDE 里看到的画面比识别用的原图小一号，但那只是预览，识别/上报用的是原图。
另外"显示"那一列（vision_check 每行末尾）就是缩放开销，嫌它拖慢帧率就加大
`SHOW_EVERY`。

⚠ 要提高分辨率换来的和换不到的东西，先想清楚再动手：
* **换不到角精度**：`fx` 和像素数同比例放大，"1 像素 = 多少度"没变；
* **换不到识别距离**：面积/长边门槛同步放大，同一距离能不能过闸门完全一样；
* **换到的是**：纸块更大 → 分割更细、边扫描/角点量化误差更小、中心更稳；
* **代价是**：检测耗时同比上涨，帧率下降（而帧率正是滞后的大头）。

判断依据在两行日志里：`[PROBE] 纯取图 = 相机+ISP 的上限`（vision_check 启动时打），
和每行的 `FPS / ms 取图 / ms 目标`。上限 40 而实际 40 → 瓶颈在采集；
上限 80 而实际 40 → 瓶颈在我们的处理。

## 三、使用步骤（顺序很重要）

1. **视觉先验**：跑 `tools/vision_check.py` ——
   看 IDE 画面里绿框是否套住 A4 靶纸、黄圈是否套住激光光斑，
   终端给出 `靶心 / 长边px / 比例 / 密度 / 对比 / 光斑 / 误差px(°)`，
   以及状态 `靶=纸(锁定)` / `确认x/3` / `搜索`（不接 H723 也能跑，只是没激光）；
   真检不到时按顺序调：`PAPER_TH`(58 → 52/64) → `PAPER_CONTRAST_MIN`；
   终端 `靶=未检出` 那行会给出亮块的 `[面积 比 密 内 外]`，照它调；
   启动那行 `[PROBE] 纯取图` 先告诉你"相机+ISP 到底能给多少帧"，别跟采集上限较劲；
2. 用它的数据定阈值、算像素焦距 `FX_PX`（`fx = 长边px × 距离m ÷ 0.275`，
   分辨率换了要乘 `S_SCALE`）；
3. **单独验云台**：只给 H723 + 电机上电（不接 K230），应为自稳状态（推一下会回位）；
4. **整机**：接上 K230 跑 `main.py`，闭环瞄准；
5. 改完任何一边，跑 `python k230_aim/tools/sync_check.py`（它会把"两边视觉代码
   不一致 / AIM 长度对不上"直接指出来），再跑 `python k230_aim/tools/pc_sim_main.py`
   确认闭环还收敛。

## 四、MicroPython 注意事项（这块固件踩过的坑）

* `math` 是裁剪版：**没有 `hypot`**（用 `sqrt`），`atan2` 也要做兜底；
* **没有 `cv2`、没有 numpy**：只用原生 `image`（`find_rects`/`find_blobs`/`draw_*`）；
* `bytearray` **不支持切片删除**（`del buf[x:]` 会报 TypeError），只能重新切片；
* IDE 想看画面必须 `Display.init(Display.ST7701, ..., to_ide=True)`；
* `machine.UART(1, tx=Pin(9))` 在这块板子上打不开（IO9/IO10 被固件预占），
  要用 `ybUtils.YbUart`（它内部就是 FPIOA + UART1）。
